# 산출물: 경로 전체 길안내 시연 (10/28, kyj)

| 파일 | 내용 |
|---|---|
| `경로1_입구에서_314호_3층.mp4` (55초) | 입구 유리문 → 엘리베이터(층 확인 후 "3층을 누르세요") → 3층 하차 → 317호로 3층 확인 → 314호 왼쪽 약 2m |
| `경로2_입구에서_4층_잘못내림.mp4` (59초) | 같은 출발 → 4층 하차 → 410호로 "여기는 4층입니다. 엘리베이터로 돌아가 3층을 누르세요" |
| `경로3_3층_엘리베이터에서_시작.mp4` (28초) | 이미 3층 엘리베이터에서 내린 곳에서 시작 → 엘리베이터 안내 없이 317호로 "3층이 맞습니다" → 314호 왼쪽 약 2m. (웹으로 같은 영상을 넣었을 때는 VLM이 첫 장면을 엘리베이터 앞으로 봐서 "층을 먼저 확인하겠습니다" → 5초에 "3층이 맞습니다. 엘리베이터를 탈 필요 없습니다"로 안내) |

- 화면 위: 목적지, 구간, 지금 층, 읽은 호실, VLM 호출 누적 (VLM을 부른 초는 노란 글씨)
- 화면 아래: 그 초에 나온 안내 문장 (4초 표시)
- 만든 방법: `video_tracker.py --mode situ` 결과(`results_guide_*_situ.jsonl`) → `src/kyj/video_route_movie.py`
- 판단 방식 (situ, 상황 기반):
  - 매 초 YOLOE + OCR + 규칙. 층은 호실 첫 자리.
  - 정해진 순서(입구 → 엘리베이터 → 하차)를 가정하지 않고, 지금 아는 사실로 정함:
    층 모름 → 층부터 확인(엘리베이터 앞이면 6초 기다려 문패를 찾고, 없을 때만 "타세요"), 목적지 층 → 복도에서 찾기, 다른 층 → 엘리베이터로 돌아가기
  - 입구 문 안내는 VLM이 장면을 입구로 볼 때만
  - VLM(qwen3-vl 4B): 장면 판단(출발, 엘리베이터 후보, 하차 직후) + 다음 행동 추천. 4B 추천은 정확도가 낮아(판단 지점 평가 0~3/17) 기록만 하고, 규칙이 사실과 모순되는 추천은 막음.
    `--advise-model`로 큰 모델을 주면 추천을 말로 안내함 (Gemini 연결 예정)

## 알려진 한계

- 방향: 문패가 어느 벽에 있는지 구분하지 않아, 반대쪽으로 가야 하는 경우(318호 경로)를 "방향이 맞습니다"로 틀림
- 엘리베이터 탔는지는 자동으로 모름 (웹은 버튼, 영상은 두 번째 파일부터)
- 도착(2m 이내) 판단은 영상이 문 앞까지 안 가서 확인 못 함
- VLM이 호출 버튼 위치를 자주 놓침

## 실시간 웹 (`src/kyj/nav_web.py`, `src/kyj/web/index.html`)

카메라 화면(또는 영상 파일)을 1초에 4장씩 서버로 보내면 같은 추적기가 안내 문장을 돌려주고, 브라우저가 소리로 읽는다.

```bash
# 서버 (학교 서버, 127.0.0.1에만 열림)
cd /workspace/capstone/src/kyj && nohup env CUDA_VISIBLE_DEVICES=3 .venv/bin/python nav_web.py --port 8765 \
  > /workspace/capstone/outputs/kyj/nav_web.log 2>&1 &
# Mac: 포트 이어 붙이고 브라우저로 http://localhost:8765
ssh -S /tmp/kyj-cnu.sock -O forward -L 8765:127.0.0.1:8765 cnu
```

- 카메라 시작: 노트북 카메라로 실시간. 엘리베이터에서 내리면 "엘리베이터에서 내렸어요" 버튼
- 영상 파일: 여러 개를 순서대로 고르면 두 번째부터 엘리베이터 하차로 처리 (예: `졸프_영상3` → `졸프_영상2`)
- 휴대폰 카메라는 https 주소가 필요해서 아직 안 됨 (localhost만 됨)
- 받은 사진과 기록: 서버 `outputs/kyj/web_sessions/<시각_호실>/`
