## 모델별 특징

### qwen3-vl:4b-instruct (우리)
- 호실 번호와 짧은 표지는 잘 읽는 편. 예: `404, 강의실 1` (사진 확인 결과 정확), `412, 강의실 5`, `313, 특수가공실`, `STAFF ONLY`
- 영어 표지판에 강함: `TOILET`, `EXIT`, `Laboratory Safety Information`
- 한국어 긴 글자는 잘못 읽고 단어를 지어냄: `프로젝트살게살`, `신학연구실`, `동물병원`, `수술실`
- 프롬프트 예시(`410호, 강의실, EXIT, 비상구`)를 베낀 답 4건
- **CPU라서 41%가 60초 초과** → 모델 성능이 아니라 실행 환경 문제

### gemma3:4b (lsh)
- 가장 많이 "읽었다"고 답함(125장). 대신 **프롬프트 예시 베끼기가 심함**
  - 예시 패턴(`410호` + `EXIT`/`비상구`/`강의실`)이 들어간 답 32건
  - **4층이 아닌 사진(3층·5층)에서 `410`이 나온 답이 41건** → 거의 확실히 지어낸 답
- 그래서 "많이 읽음"이 "잘 읽음"을 뜻하지 않는다

### qwen2.5vl:7b (sjh)

- 공대 건물에 없는 단어(`병동 입구`, `의료원 환자 허가서`)도 나옴

## 같은 모델, 다른 실행: qwen3-vl 우리(CPU) vs cjy(GPU), 3층 51장
- 둘 다 답을 낸 25장 중 **답이 완전히 같은 건 11장, 다른 건 14장**
  - cjy 실행은 temperature를 고정하지 않아서 실행할 때마다 답이 달라질 수 있음
  - Ollama 버전도 다름 (0.34.4 vs 0.24.0)
- **GPU인데도 60초 초과가 12장**. 같은 단어를 계속 반복하는 답이 보임
  - 예: `이용안내, 상황실, 상황실, 상황실, 상황실, …`
  - 답 생성이 반복에 빠져 끝나지 않는 것으로 보임 → 답 길이 제한(`num_predict`)이 필요
- 호실 번호는 둘 다 답을 낸 경우 4/4 일치

## 지금까지의 잠정 결론
1. **실행 환경이 결과를 좌우하고 있다.** CPU 모델은 시간 초과 때문에 성능이 깎여 보인다. GPU로 통일하기 전까지 모델끼리 순위를 매기면 안 된다.
2. **프롬프트 예시가 오답을 만든다.** 특히 gemma3에서 심하고 qwen3-vl에서도 보인다.
3. 모델마다 성향이 극단적으로 다르다: gemma3는 지어냄, qwen2.5vl은 "글자 없음"으로 회피, minicpm은 설명문을 씀.
4. qwen3-vl:4b는 숫자와 영어에서 가장 안정적으로 보인다. GPU로 다시 돌리고 GT로 채점해서 확인해야 한다.
