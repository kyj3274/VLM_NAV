## 1. 무엇을 만들고 있나

시각장애인이 처음 가는 건물에서 **말 안내만 듣고 목적지 호실까지** 가게 하는 제로샷 실내 길안내다.

```
카메라(1초 4~8장) → 가장 선명한 장
   → YOLOE(물체) + OCR(글자)                     매 초, 약 0.7초
   → 규칙 추적기 (층 = 문패 첫 자리, 지나온 문패, 장면)   매 초
   → VLM qwen3-vl 4B (장면 판단)                   사건이 있을 때만, 경로당 5~8번
   → 안내 문장 → 음성
```

## 3. 실험에서 얻은 결론 5가지

1. **VLM에게 글자를 "쓰게" 하지 말고 "고르게" 한다.**
   - 호실은 OCR이 읽고 VLM은 조각을 확인만 한다. 이렇게 해서 F1이 25에서 90이 됐다.
   - lsh 영상 실험에서도 VLM이 호실을 다시 적으면 OCR보다 덜 읽었다 (27 → 17).
2. **VLM을 매 프레임 부르지 않는다.**
   - 매 프레임 부르면 장당 약 9초가 걸리고, 답은 대부분 "정면 관찰"이다 (lsh 88장 중 75~85장).
   - 규칙 추적기 + 사건 때만 VLM으로 바꾸니 경로당 VLM 호출이 87번에서 5~8번이 됐다.
3. **4B는 "한 단계"는 하지만 "여러 단계 조합"은 못 한다.**
   - 질문을 쪼개면 층은 17/17이다. 다음 행동을 한 번에 고르게 하면 0~3/17이다.
   - 그래서 형식과 조합은 규칙이 맡는다.
4. **판단은 큰 모델이 된다.**
   - Gemini 3.5 Flash는 같은 질문에서 15/17을 맞혔고, 규칙이 틀리는 "반대로 가는 중"도 맞혔다.
   - 기록만 줘도 14/17이다. 판단에는 사진보다 지나온 기록이 중요하다.
5. **복도 번호는 벽마다 따로 순서대로다.**
   - 왼쪽은 317 → 316 → 315 → 314 → 313, 오른쪽은 309 → 307이다.
   - 한 줄로 섞으면 방향 판단이 틀린다. "홀수끼리·짝수끼리"는 틀린 해결책이다.

## 5. 10/29에 바뀐 것

- **선명한 장 기본값** (lsh 아이디어): 호실 맞음 24 → 29, 놓침 8 → 4. 다시 보기가 약 25% 줄었다. 안내 결과는 같다.
- **버그 수정**: 층을 두 번 바꿔 내리면 "잘못 내린 층" 상태가 남아 목적지 안내가 막혔다.
- **팀 형식으로 채점**: 안내 출력은 그대로 두고 채점용으로만 바꿨다.
  - 정답표 기준 호실은 추적기 28/2/5, lsh 17/6/10이다 (맞음/잘못/놓침).
  - cjy 평가 AI(4B)는 개수 검사 실패가 많고(추적기 23/44) 판정 오류가 커서 참고만 한다.
- **성능 변화 요약**: 문패 인식이 조금 좋아지고 조금 빨라졌다. **판단 능력은 그대로다.**

## 6. 아직 안 되는 것

1. 방향 판단: 벽 구분을 안 한다. 318호 경로가 틀린다.
2. 도착 판정: 문 옆을 지나가는 순간을 못 잡는다.
3. 판단: 4B 추천은 기록만 하고 말로 내보내지 않는다. 큰 모델은 아직 실제 경로에 안 붙였다 (Gemini 무료 한도 하루 20번).
4. 랜드마크 오탐: 출입문, 화장실표시, 비상구표시.
5. 엘리베이터를 탔는지 자동으로 모른다 (웹은 버튼).
6. 평가 규모가 작다: 영상 3개, 판단 지점 17개, 정답표는 우리가 만들었다.

## 7. 다음 순서 (효과 큰 순)

1. **방향 판단**: 벽별 번호 추세. 확신이 없으면 "아직 목적지 문패가 안 보입니다"로 물러난다.
2. **판단을 큰 모델에**: `--advise-model`로 Gemini를 붙인다. 경로당 3~5번 부르고, 규칙이 모순을 막는다.
3. **도착 판정**: 목적지 문패가 화면 옆으로 빠져나가는 순간을 "문 옆을 지남"으로 본다.
4. **영상 더 찍기**: 다른 층·건물, 문 앞 도착, 꺾인 복도, 엘리베이터 안.
5. **팀 평가 기준 논의 (cjy)**: 영상용 "기록 근거" 항목과 평가 모델 크기.
