## 1. 시뮬레이터 (`src/sim/`)

인식은 기하로 대신하고, 안내 문장을 글자 그대로 따르는 가상 사용자로 **Claude 버전 `Navigator`를 고치지 않고 그대로** 넣어 돌립니다. 크레딧 0, 수백 번을 몇 분에 돌립니다.

인식과 사용자는 이렇게 둡니다.
- **인식(기하로 대신함):** 시야 60°, 문패 5m, 비스듬히 80°까지 읽음
- **가상 사용자:** "뒤로 돌아"를 들으면 돌고, "왼쪽 복도"를 들으면 다음 갈림길에서 꺾음. "좌우로 비춰"는 휴대폰만 돌리고, "한 바퀴"는 제자리에서 돎. "N시 방향"을 들으면 그쪽으로 몸을 돌림

| 파일 | 환경 |
|---|---|
| `world.py`, `bench.py` | 직선 복도: 번호 배치 5종과 실험 건물 3·4층. 인식 지연·오류, 이유 없이 도는 사용자, 방위 없음 |
| `floor.py`, `bench_floor.py` | 갈림길 있는 층 6종(ㄱ·T·+·H·빗·ㅁ자). 번호 / 한글 이름 / 영어 이름 문패, 갈림길 표지판 |
| `lobby.py` | 넓은 로비(16·24·36m). 벽 따라 걷기, 가운데 장소(섬: 안내데스크·카페) |
| `stress.py` | 판단 코드는 그대로 두고 조건만 바꿈: 없는 목적지, 센서 오차(방위 치우침·흔들림, 걸음 길이), 인식 놓침 |
| `view.py`, `view_floor.py` | 위에서 본 그림과 안내 문장 재생 화면 (`outputs/sim/`) |

```

.venv/bin/python src/sim/bench_floor.py --n 10 --mode number|name|english [--signs 1]

```

## 2. 시뮬레이터로 찾고 고친 것

### 공통 판단 `core/` (Claude·로컬 둘 다 바뀜)

| 문제 (시뮬레이터에서 본 것) | 고친 것 |
|---|---|
| 꺾인 복도에서 전 복도의 번호 흐름으로 "뒤로 돌아"를 되풀이 | `core/floor_graph.py`(새 파일): 걸음 수·방위로 대략 위치를 잡고 갈림길과 가지를 기억해 어느 복도로 갈지 고름. 갈림길 없이 꺾여도(방위 축이 바뀜) 새 직선으로 보고 복도 번호 흐름을 새로 시작 |
| 갈림길 판단과 깊이 '막다른 곳'이 엇갈려 오감 | 앞에 갈림길이 보이면 깊이 막다른 곳 판단을 하지 않음 |
| 목적지가 갈림길 앞에 있는데 갈림길이 "뒤로" | 갈림길 판단이 지금 복도를 고르면 복도 안 방향은 번호 흐름에 맡김 |
| 이름만 있는 층·다른 언어 표지판 | 표지판에 목적지 이름이 보이면 그 가지를 고름 |
| 목적지 앞에서 엉뚱한 쪽을 비추게 함 (1차원 거리만 기억) | `core/arrival.py`: 목적지를 평면 점(본 자리 + 거리, 방위)으로 기억.<br>· 옆으로 2.5m 넘게 떨어지면 "N시 방향 약 M미터"<br>· 뒤에 있으면 "뒤쪽"<br>· 1m 안에 오면 옆 비추기<br>· 좌우가 0.6m 안이면 "정면, 좌우로 비춰 주세요" (센서 오차로 좌우가 뒤집히는 것 방지)<br>걸음 수나 방위가 없으면 전처럼 1차원으로 계산 |
| 비추는 중 사진 속 위치로 좌우가 바뀜 | 비추라고 한 쪽을 유지 |
| 조사가 어색함 ("410호는", "카페은") | 받침에 맞게 은/는, 이/가 |

### Claude 버전 `navigator.py`

| 문제 | 고친 것 |
|---|---|
| 로비에서 벽만 따라 걸어 가운데 장소를 못 봄 | 목적지를 못 본 채 12m 걸을 때마다 "제자리에서 천천히 한 바퀴 돌아 주세요"(사진 8장). 본 쪽을 지금 향한 쪽 기준 시계 방향으로 알림. 이미 둘러본 자리 근처에서는 다시 돌지 않음 |
| 없는 목적지를 끝없이 찾음 | 로비에서 새 곳에 못 가고 40m를 다니면 "이 층에서 목적지를 찾지 못했습니다. 주변 분께 물어봐 주세요." (층 전체에 넣으면 성공률이 떨어져 로비만) |
| 앞서 찍은 사진의 판단을 말할 때 그 사이 돈 것을 모름 | 웹 서버가 가장 최근 센서를 넘겨 반영 (지연 보정) |

## 4. PR #3와 합치기 (간단히)

- 팀원의 "내린 뒤 둘러보기"(`st["scan"]`)와 로비 둘러보기의 이름이 겹쳐, 로비 쪽을 `st["lscan"]`으로 분리했습니다.
- **"지나침" 처리:**
  - 옆을 비추라고 한 뒤 1.5m 넘게 걸어서 다른 문패를 읽었고 그래프도 지나쳤다고 보면, "가능성 높음" 대신 "지나친 것 같습니다, 뒤로 돌아"라고 합니다.
  - 걸음 수가 없으면 이 조건 없이 판단합니다.
- 팀원 테스트 4개의 기대값을 바꿨습니다(이유는 테스트 주석).
  - "지나침" 2개
  - "○호를 지났습니다"의 번호 2개: 아직 앞에 있는 문패 대신 지난 문패를 말합니다.
- 시뮬레이터는 센서를 `step()` 인자로 넘깁니다. 팀원의 방향 문장 "○호는 왼쪽일 가능성이 높습니다"를 도착으로 세지 않게 했습니다.

## 5. 한계와 남은 일

- **센서 판단은 실제 데이터로 아직 확인하지 못했습니다.** 받은 기록 36개 모두 걸음 수 0, 방위 없음이었습니다. 다음 휴대폰 시험에서는 시작 전에 "동작 및 방향 접근"을 허용하고, 기록에 값이 들어오는지 확인합니다.
- **이 값들은 시뮬레이터로 정했습니다:**
  - `SCAN_M` 12m, `GIVE_UP_M` 40m
  - `PASS_WALK_M` 1.5m
  - `REACH` 2.5m, `SIDE_MIN` 0.6m

  한 건물에 맞춘 값은 아니지만 시뮬레이터 가정(문패 5m, 간판 12m)에 기대므로 실제 사진으로 확인해야 합니다.
- **실제 인식에는 갈림길 칸이 없습니다.** 지금 Claude 인식은 갈림길(옆이 트임)을 주지 않아, 실제 사용에서는 갈림길 판단이 거의 작동하지 않습니다. 인식에 칸을 더하는 것은 실제 사진으로 확인하며 합니다.
- **ㅁ자 층에서 없는 목적지를 찾으면 오래 헤맵니다.** 걸음 추정이 틀어지면 같은 갈림길을 못 알아보기 때문입니다. 기억을 "걸은 길 + 본 것" 지도 하나로 합치고 문패로 위치를 바로잡는 구조 변경과 함께 다룰 예정입니다.
- PR #3 확인 요청인 xfail(한 벽에 문패가 하나뿐이면 다른 벽 흐름만 봄)은 아직 그대로입니다.
