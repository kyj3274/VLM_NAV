# 2026-10-04 작업일지 (kyj)

시각은 한국시간(KST) 기준. 서버 로그는 UTC로 찍혀 있으니 +9시간.

## 한 줄 요약

새 모델 **qwen3-vl:4b-instruct**를 학교 서버에 받아서, 팀 표준 표지판 OCR(signs) 프롬프트로 3·4·5층 226장을 돌렸다.
서버 Ollama가 CPU로만 돌아서 33%가 60초 초과로 실패했고, 결과를 사진과 맞춰보는 검수 페이지를 로컬에 만들었다.

## 진행 순서

### 1. 서버 현황 파악 (조회만)
- 9/30 이후 바뀐 점
  - 사진 172장 → 233장 (3층 101 / 4층 81 / 5층 44 / stairs 7)
  - lsh(gemma3:4b)와 sjh(qwen2.5vl:7b)가 signs 실험을 3·4·5층 완료
  - lsh가 만든 `src/lsh/sign.py`가 사실상 팀 공용 스크립트 (sjh는 `MODEL`과 `OUTPUT_DIR` 두 줄만 바꿔서 사용)
- **Ollama가 CPU로만 도는 원인**: `/workspace/ollama.log`
  ```
  NVIDIA driver too old  device="Tesla P100" compute=6.0  driver=535  required_driver="550 or newer"
  inference compute  id=cpu
  ```
  Ollama 최신 버전은 P100을 쓰려면 드라이버 550 이상이 필요한데 서버는 535. 모델 문제가 아니라 Ollama와 드라이버 버전 문제다.

### 2. 모델 선택
- 원래 원한 것: Qwen3-VL-4B-Instruct 4bit
  - `...-4bit` 이름의 배포본은 Mac(MLX)용이라 서버에서 못 씀
  - HF 원본은 venv의 transformers 4.49가 지원하지 않고, 팀 규칙(Ollama만 사용)과도 충돌
- 결정: **Ollama `qwen3-vl:4b-instruct`** (q4_K_M, 3.3GB)
  - Ollama 모델은 기본이 4bit라 다른 팀원 모델과 양자화 조건이 같음
  - thinking 버전은 느리고 JSON 출력에 불리해서 제외

### 3. 스크립트 작성: `src/kyj/run_task.py`
팀 템플릿(lsh `sign.py`) 구조를 유지하고 아래를 추가했다.

| 추가 | 이유 |
|---|---|
| `--task perception / navigation / signs` | Task 3개를 한 파일에서 실행. signs는 **팀 프롬프트 그대로** |
| `--model`, `--floor`, `--limit`, `--start` | 층이나 모델을 바꿀 때마다 코드를 고치지 않아도 됨 |
| `options: temperature 0, seed 42` | 같은 사진에 늘 같은 답이 나오게 (팀원 스크립트에는 없음) |
| 사진 번호순 정렬 (1, 2, …, 10) | 기존 스크립트는 1, 10, 100, 2 순서 |
| 결과에 `floor`, `task` 기록 | 층마다 파일명(1.jpeg)이 겹침 |

1024px, JPEG 85, 60초 제한, warm-up은 `sign.py`와 같게 맞췄다.
Mac에서 가짜 Ollama 응답으로 테스트한 뒤 서버에 올렸다.

### 6. 실행 중 발견한 것
- **3층 사진 101장 중 50장이 중복** (md5 일치). 서로 다른 사진은 51장. 팀원 3층 결과도 같은 영향을 받는다.
- **cjy가 GPU 문제를 해결함**: 예전 버전 Ollama 0.24.0을 `tools/`에 설치하고 `11435` 포트 + GPU 6번으로 실행 → `100% GPU`
  - 기존 `11434` 포트(0.35.1)는 여전히 CPU
- cjy가 같은 모델(qwen3-vl:4b-instruct)로 3층을 GPU에서 돌림 → 실험이 겹침

### 7. 검수 페이지 (Mac 로컬 전용)
- 위치: `review/review.html`
- 사진 축소본 176장(중복 제외, 12MB)과 팀원 결과 파일을 서버에서 **읽기만** 해서 Mac으로 가져옴
- 사진 옆에 5개 모델의 답을 나란히 보여주고, 정답을 입력하면 자동 채점(정밀도, 재현율, F1)
- 정답은 CSV로 저장하고 불러올 수 있어서 팀원과 나눠서 입력할 수 있음
- 새 결과 반영: `results/`에 jsonl 추가 → `build_review.py`의 `MODELS` 수정 → `python3 build_review.py`
