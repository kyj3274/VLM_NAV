- **qwen3-vl과 qwen2.5vl이 같은 호실 번호를 내면 16개 모두 맞았다 (P 100%).**

## 3. 평가 방법

### 3-1. 정답 없이 보는 지표 (`compare_fields.py`)
| 지표 | 계산 방법 | 무엇을 알 수 있나 |
|---|---|---|
| rooms 층 일치 | 호실 번호 첫 자리 = 사진의 층 | 3층 사진에 `1xx`, `9xx`가 나오면 지어낸 것 |
| 예시 베끼기 | rooms에 `999`가 들어간 개수 | 프롬프트 예시 의존도 |
| 번호 줄줄이 세기 | `101, 102, 103, 104`처럼 1씩 늘어나는 번호가 4개 이상 | 반복 루프 |
| 층별 랜드마크 | 한 층에만 있는 랜드마크가 다른 층 사진에 나온 수 | 목록에서 골라 담기 |
| 방향 규칙 위반 | 사진 속 위치에 11/12/1시 외의 값, 허용 대상 7개 밖의 대상 | 프롬프트 규칙 준수 |

### 3-2. 사진 조사와 비교 (`score_vs_survey.py`)
- **사진 조사 만드는 법**
  1. 보조 에이전트 3개가 층을 하나씩 맡아, 축소 사진(1000px) 176장을 한 장씩 열었다.
  2. 보이는 랜드마크(23개 이름), 읽을 수 있는 호실 번호, 그려진 화살표, 층 표시를 기록했다.
  3. 확실하지 않은 것은 뺐다. 호실 번호와 화살표는 원본을 확대한 조각을 만들어 다시 확인했다.
- **저장 위치**: `review/survey/survey_{3F,4F,5F}.json`
- **규모**: 호실 번호가 읽힌 사진 62장(번호 71개), 화살표가 있는 사진 5장, 층 표시가 있는 사진 9장
- **채점**: 사진마다 조사 기록과 모델 답을 집합으로 비교해 TP / FP / FN을 센다. 이를 전체 합산(micro)해서 P / R / F1을 낸다.
  - 실패한 사진은 빈 답으로 친다.
  - 화살표는 "화살표가 있는 사진을 찾았는지"(사진 단위)와 "방향이 ±1시간 안에 맞았는지"를 본다.
- **한계**
  - 사진 조사도 AI가 축소 사진을 보고 적은 것이다. 놓친 것도, 잘못 본 것도 있을 수 있다.
  - 예: CCTV와 소화기함은 생김새로만 판단해서 불확실하다.

## 5. 코드 구성

### 5-1. `src/kyj/run_task.py` (실행, 서버와 Mac이 같은 파일)
팀 공용 `sign.py`(lsh)의 구조를 유지하고, task·모델·실행 조건을 실행 옵션으로 바꿀 수 있게 했다.

```
run_task.py
├── 공통 설정         OLLAMA_URL, DATA_ROOT, OUTPUT_DIR, MAX_SIDE=1024, JPEG_QUALITY=85,
│                    REQUEST_TIMEOUT_SECONDS=60, OPTIONS={temperature 0, seed 42}
├── fields 설정       FIELDS_PROMPT_VERSION="p2", LANDMARKS(23개), POSITION_TARGETS(7개),
│                    DIRECTION_VALUES(12시~11시, 판단 불가)
├── TASKS             task마다 {schema, prompt}
│   ├── perception    상황 인식 5항목
│   ├── navigation    410호 가는 방향 (시계 방향)
│   ├── signs         글자 읽기 (lsh sign.py와 같음)
│   └── fields        이동 단서 5항목 (이번 실험)
├── encode_image()    긴 변을 MAX_SIDE로 축소 → JPEG → base64
├── image_id()        3rdFloor/6.jpeg → 3F_006
├── drop_duplicates() md5가 같은 사진은 첫 장만 남김
├── run_one()         사진 1장 → Ollama /api/chat (format = schema) → 결과 레코드
├── warm_up()         첫 요청 전에 모델을 GPU에 올려 둠
└── main()            옵션 처리 → 사진 목록 → 1장씩 실행하고 결과를 바로 jsonl에 추가
```

**fields schema 요약**
```
rooms, floors, spaces : 문자열 배열
landmarks             : 23개 이름 중에서만 (enum)
directions            : [{target: 문자열, type: SIGN_ARROW | RELATIVE_POSITION,
                          value: 12시~11시 | 판단 불가}]
```

**실행 옵션**

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--model` | `qwen3-vl:4b-instruct` | Ollama 모델 이름 |
| `--task` | (필수) | `fields` / `signs` / `perception` / `navigation` |
| `--floor` | `all` | `all`이면 3·4·5층 (stairs는 따로 지정할 때만) |
| `--dedupe` | 꺼짐 | 중복 사진 제외 |
| `--ids` | - | 이 사진 ID만 (`4F_046,5F_010` 또는 ID 목록 파일) |
| `--ollama-url` | `http://127.0.0.1:11434` | GPU 서버는 `http://127.0.0.1:11436` |
| `--max-side` | 1024 | 해상도 실험용. `0`이면 원본 |
| `--num-predict` | 없음 | 최대 출력 토큰 (fields는 512) |
| `--timeout` | 60 | 사진 1장 제한 시간(초) |
| `--start` / `--limit` / `--tag` | - | 중간부터 이어서 / 앞에서 N장만 / 결과 파일명에 메모 |

**실제 실행 명령**
```bash
cd /workspace/capstone
.venv/bin/python src/kyj/run_task.py --model qwen2.5vl:7b --task fields --floor all --dedupe \
  --ollama-url http://127.0.0.1:11436 --num-predict 512 --tag gpu7_1024
```

## 8. 한계

- **사람 정답(GT)이 없다.** 6절의 P/R/F1은 사진 조사 기준의 참고 일치율이다. 사진 조사 자체에도 놓침과 오판이 있을 수 있다.
- **사진 조사의 호실 번호와 화살표는 적다** (번호 71개, 화살표 사진 5장). 특히 화살표 결과는 사진 수가 너무 적어 순위를 매기기 어렵다.
- **3층은 원본 해상도가 낮다** (1058×1411). 층별 차이에 해상도 차이가 섞여 있다.
- **프롬프트 하나(p2)로만 본 결과다.** 프롬프트를 바꾸면 순위가 달라질 수 있다.
