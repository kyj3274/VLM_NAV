## 2. lsh 결과를 kyj 정답표로 채점

- **정답표**: `data/video/frame_gt.json` (1초 1장).
  - 10/29에 2개를 추가했다: 4층 0초 410, 3층 19초 314. 둘 다 lsh OCR이 읽어서 프레임을 확인한 것이다.
  - 그래서 정답 호실은 33개에서 35개가 됐다.
- **채점 범위**: 3층·4층 복도, ±1초 허용.

| 방식 | 프레임 | 맞음 | 잘못 냄 | 놓침 | 문패 읽음 (/11) |
|---|---|---|---|---|---|
| lsh OCR (1단계) | 구간 첫 장 | 12 | 7 | 13 | 10 |
| lsh OCR (1단계) | **가장 선명한 장** | **27** | 6 | **4** | **11** |
| lsh VLM image | 가장 선명한 장 | 17 | 6 | 10 | 9 |
| lsh VLM json | 가장 선명한 장 | 19 | 4 | 9 | 9 |
| kyj 1단계 (`results_stage1`) | 1초 1장 | 18 | 4 | 7 | 10 |

- 같은 OCR인데도 **선명한 장을 고르면 놓침이 13에서 4로** 준다. 걷는 영상은 흔들림이 크기 때문이다. lsh 측정으로 선명도 중앙값이 1.5~1.9배다.
- VLM이 호실을 다시 적게 하면 OCR보다 덜 읽는다 (27 → 17~19). **호실은 OCR 결과를 그대로 쓰는 것이 낫다.**
- **랜드마크**는 VLM이 YOLOE보다 나아지지 않았다.
  - 엘리베이터는 YOLOE 맞음 4 / 오탐 52이고, VLM image는 맞음 0 / 오탐 13이다.
  - 출입문은 둘 다 대부분 놓친다.
- **다음 행동**은 image 모드에서 OBSERVE [12,3]이 75~83장이다. MOVE는 4~10장뿐이다. 이전 장면 기록 없이 사진 1장만 보면 매번 "앞을 보라"가 된다.

## 3. 실험 1: 대표 프레임 = 첫 장 vs 가장 선명한 장 (kyj 추적기, situ)

- **설정**: `video_tracker.py --mode situ --key first|sharp`.
  - sharp는 1초의 8장 중 선명도(라플라시안 분산, 긴 변 640)가 가장 큰 장으로 1단계를 돌린다.
  - 애매하면 8장을 모두 다시 보는 것은 같다.

### 3-1. 호실 읽기 (정답 35개)

| 경로 | 대표 프레임 | 맞음 | 잘못 냄 | 놓침 | 문패 읽음 |
|---|---|---|---|---|---|
| 314 (1 → 3층, 1 → 4층) | 첫 장 | 24 | 1 | 8 | 11/11 |
| 314 (1 → 3층, 1 → 4층) | **선명한 장** | **29** | 3 | **4** | 11/11 |
| 410 (1 → 3층 → 4층) | 첫 장 | 25 | 1 | 5 | 10/11 |
| 410 (1 → 3층 → 4층) | 선명한 장 | 28 | 2 | 5 | 10/11 |

- 선명한 장이 더 많이 읽는다. 잘못 낸 번호는 1~2개 늘었다.
  - 늘어난 오독은 3층 7초 오른쪽 비스듬한 309 문패를 300·310으로 읽은 것이다.
- 410 경로의 "못 읽은 문패"는 3층의 314다. 410 경로에서는 3층을 잘못 내린 층으로 보고 돌아가라고 안내한 뒤라 3층 끝까지 읽을 필요가 없다.

### 3-2. 다시 보기 구간과 시간

| 경로 | 다시 본 구간 (첫 장 → 선명한 장) | 1초 처리 평균 (첫 장 → 선명한 장) |
|---|---|---|
| 410: 1 → 3층 → 4층 (88초) | 61 → **45** | 1.23 → **1.09초** |
| 410: 1 → 4층 (60초) | 47 → **37** | 1.34 → **1.24초** |
| 314: 1 → 3층 (56초) | 41 → 31 | 1.92 → 1.28초 * |
| 314: 1 → 4층 (60초) | 22 → 12 | 1.19 → 0.80초 * |
| 318: 1 → 3층 (56초) | 43 → 33 | 1.92 → 1.32초 * |

\* 314·318의 첫 장 결과는 10/28에 돌린 것이라 서버 부하가 달랐다. 시간 차이는 참고만 하고, 다시 본 구간 수로 비교한다. 410 두 줄은 같은 날 연달아 돌린 것이다.

- 첫 장이 흐리면 "흐림"으로 8장을 다 다시 보게 된다. 선명한 장을 고르면 이 경우가 줄어 **다시 보기가 약 25% 줄고 시간도 준다.**
- **안내 문장은 314·318 경로 모두 같았다.**
  - 314는 3층 확인 후 314호 왼쪽 약 2 m, 4층에서는 돌아가기.
  - 318의 방향 오류는 그대로다.
- **단점**: 1초 안에 잠깐만 보이는 문패는 놓칠 수 있다.
  - 예: 4층 0초의 410은 첫 장에만 보인다.
  - 첫 장 방식은 0초에 "4층이 맞습니다, 410호 근처"라고 했고, 선명한 장 방식은 3초에 했다.

**결정**: 선명한 장을 기본으로 쓰는 것이 낫다. 웹(`nav_web.py`)에는 아직 넣지 않았다 (지금 기본은 첫 장).

> **버그 수정 (10/29 오후)**: 처음 실행에서는 4층에서 "410호가 보입니다"가 나오지 않았다.
> - 원인: 3층에서 켜진 "잘못 내린 층" 상태가 엘리베이터를 다시 타고 4층에 내린 뒤에도 남아 있었다. 그래서 목적지 안내가 막혔다.
> - 고침: 엘리베이터에서 내릴 때(`new_segment`)와 층 판단이 바뀔 때 이 상태를 다시 정한다.
> - 위 표는 고친 뒤 결과다. 314·318 경로는 층을 한 번만 내려서 영향이 없었다.

- 1 → 4층 바로 가는 경로에서는 이렇게 안내했다.
  - 4층 0~3초: "목적지 410호가 왼쪽 앞에 보입니다, 약 4~6 m"
  - 4층 4초: "약 3 m"
  - 실제로 410호는 왼쪽 벽이다 ✅.
- **처음 보는 목적지(410)와 처음 보는 경로(3층을 거쳐 4층)에서도 층 판단과 되돌아가기가 맞았다.** 호실 목록이나 410 전용 규칙은 넣지 않았다.
- VLM 호출은 경로당 6번이고, 1초 처리 중앙값은 1.2초다. lsh 방식은 88장에 VLM 88번, 장당 8.6초다.

**안 된 것**
- **도착을 선언하지 못했다.**
  - 사용자는 5초쯤 410호 문을 지나간다. 추적기의 거리 추정은 최소 3 m였다 (기준 2 m).
  - lsh 글자 높이 규칙도 도착이 안 나왔다.
  - 둘 다 "문 옆을 지나갈 때"를 도착으로 못 잡는다. 문패가 화면 옆으로 빠져나가는 순간(마지막으로 본 위치와 방향)을 쓰는 규칙이 필요하다.
- **4B의 다음 행동 추천은 여전히 틀린다.**
  - 1층 시작에서 "엘리베이터로 돌아가기"를 추천했고, 규칙이 막았다.
  - 4층에서는 "문 통과"를 추천했다.
  - 기록만 하고 말로는 내보내지 않으므로 안내에는 영향이 없다.

## 5. 방식 비교 (같은 영상)

| | lsh `run_video_nav.py` | kyj `video_tracker.py --mode situ` |
|---|---|---|
| VLM 호출 | 매 프레임 (88장 × image·json) | 사건이 있을 때만 (경로당 5~6번) |
| 1장 또는 1초 시간 | VLM 중앙값 8.6초 (fallback 17.5초) | 중앙값 1.2초, VLM을 부르는 초는 6~7초 |
| 출력 | 팀 형식 JSON (시각정보 / 상황_맥락 / 방향정보 / 요청) | 안내 문장 + 상태 (층, 호실, 거리, 방향) |
| 맥락 | 없음 (장마다 따로) | 층, 지나온 문패, 사건 기록을 이어서 씀 |
| 호실 | VLM이 OCR 결과를 보고 다시 적음 | OCR + 첫 자리 다수결 + 8장 투표 |
| 다음 행동 | OBSERVE/MOVE + 시계 방향. 대부분 OBSERVE [12,3] | 규칙(층, 장면) + VLM 장면 판단. 다음 행동 추천은 큰 모델용 |
| 정답 채점 | 없음 | 프레임별 정답표, 판단 지점 17개 |

- lsh의 **팀 형식 출력은 cjy 평가 기준과 맞춘 것**이라 평가용으로는 의미가 있다. 그래서 7절에서 추적기 결과를 이 형식으로 바꿔 채점했다.

## 7. 반영 2: 팀 형식으로 내보내 채점 (채점용, 안내 출력은 그대로)

### 7-1. 방식

```
영상/카메라 → 추적기 → 안내 문장 + 상태 기록   ← 실제 출력 (바뀌지 않음)
                         └─(나중에, 따로) video_team_format.py → 팀 형식 JSON(1초 1개) → 채점
```

- **안내 출력은 바뀌지 않는다.** 바꾸는 일은 다 끝난 기록 파일을 읽어서 따로 한다. VLM도 더 부르지 않는다.
- 추적기 기록에는 `seen` 칸만 늘었다. 문패 방향, 대표 장면의 층표시·랜드마크를 담는다.
- 칸별로 옮긴 내용은 이렇다.

| 팀 형식 칸 | 추적기에서 가져온 것 |
|---|---|
| 호실_표지판 | 8장 투표로 확정한 호실 + 방향 (11/12/1시) |
| 층표시_표지판 | 대표 장면의 OCR 층표시 |
| others | YOLOE 랜드마크. 엘리베이터는 VLM이 장면을 엘리베이터 앞으로 봤을 때만 |
| 공간이름 / 판단근거 | VLM 장면 판단 + 문패와 층 추론 근거 |
| 목적지와의_관계 | 층 비교(목적지 층 / 다른 층 / 모름), 목적지 문패를 봤는지와 거리 |
| 다음_행동 | 그 순간의 안내를 옮김. 복도 따라 가기·문 통과 → MOVE [12, 2], 돌아가기 → MOVE [6, 3], 목적지 보임 → MOVE [그쪽 방향, 거리], 엘리베이터 앞에서 둘러보기 → OBSERVE [12, 3] |
| 인식한_목적지_텍스트 | "410호" |

- **주의**: "복도를 따라 문패를 찾으며 가세요" 같은 안내를 숫자 하나(MOVE [12, 2])로 옮기는 것은 근사다. 이 칸의 점수는 안내 품질 그대로가 아니다.

### 7-2. 결과 ① kyj 정답표로 채점 (410호, 1층 → 3층 → 4층, 88초)

| 항목 | kyj 추적기 (팀 형식) | lsh (image, 매 프레임 VLM) |
|---|---|---|
| 호실 맞음 / 잘못 / 놓침 | **28 / 2 / 5** | 17 / 6 / 10 |
| 출입문 맞음 / 잘못 / 놓침 | **56** / 28 / 1 | 5 / 0 / 52 |
| 엘리베이터 맞음 / 잘못 / 놓침 | 1 / **0** / 11 | 0 / 13 / 12 |
| 비상구표시 맞음 / 잘못 / 놓침 | 1 / 11 / 6 | 0 / 0 / 7 |
| 화장실표시 잘못 냄 | 10 | 1 |
| 다음 행동 분포 | MOVE 정면 57, MOVE 뒤(돌아가기) 24, OBSERVE 6, MOVE 왼쪽 1 | OBSERVE 정면 75, MOVE 정면 9, MOVE 왼쪽 1 |
| VLM 호출 | 경로 전체 8번 | 85번 |

- **호실은 추적기가 확실히 낫다.** 8장 투표와 선명한 장 덕분이다.
- **랜드마크는 서로 반대로 틀린다.** 추적기는 YOLOE를 그대로 써서 출입문을 많이 찾는 대신 오탐이 있다 (출입문 28, 화장실표시 10, 비상구표시 11). lsh는 VLM이 거의 안 적어서 놓침이 많다.
- **엘리베이터는 추적기 쪽이 오탐 0이다.** "VLM 장면 판단이 엘리베이터 앞일 때만" 조건 덕분이다. 대신 놓침이 11이다.
- 다음 행동은 추적기가 상황에 따라 바뀐다. 3층에서는 돌아가기, 4층에서는 410호 쪽이다. lsh는 거의 "정면 관찰"이다.

### 7-3. 결과 ② cjy 평가기(qwen3-vl 4B 평가 AI)로 채점 (같은 경로, 2초 간격 44장)

- cjy의 `src/cjy/evaluate.py`를 **고치지 않고 그대로** 실행했다. 결과는 kyj 폴더에 썼다.
- 1장에 약 41초가 걸린다. 그래서 88장 대신 2초 간격 44장만 채점했다.

| | kyj 추적기 | lsh image |
|---|---|---|
| **평가 실패** (평가 AI 출력이 cjy 검사를 통과 못함) | **23 / 44** | 3 / 44 |
| 호실_표지판 TP / FP / FN | 6 / 8 / 2 | 4 / 15 / 3 |
| 층표시_표지판 TP / FP / FN | 1 / 0 / 0 | 4 / 20 / 0 |
| others TP / FP / FN | 23 / 0 / 0 | 18 / 7 / 0 |
| 공간이름_및_판단근거 (/2) | 1.00 | 2.00 |
| 목적지와의_관계 (/2) | 0.43 | 1.29 |
| 다음_행동_방향 (/2) | 0.00 | 0.20 |
| 인식한_목적지_텍스트 (/2) | 1.14 | 1.12 |

**이 점수는 그대로 믿기 어렵다.** 이유는 넷이다.

1. **평가 실패가 한쪽에 몰렸다.**
   - 실패는 모두 "others.출입문: TP+FP must equal N"처럼 평가 AI가 개수를 잘못 센 것이다.
   - 추적기는 랜드마크를 많이 내서 실패가 23건이고, 남은 21장은 랜드마크가 적은 장 위주다.
   - 그래서 두 쪽이 같은 조건에서 채점되지 않았다.
2. **평가 AI가 명백히 틀린다.**
   - "410호"를 출력했는데 "목적지를 인식하지 못함"으로 0점을 줬다. 그래서 목적지 인식이 두 쪽 모두 약 1.1/2다.
   - 곧은 복도에서 정면 이동(MOVE [12, 2])을 "사진과 모순"이라며 모두 0점을 줬다.
   - 정답표로는 맞는 호실 다수를 FP로 셌다. 정답표 기준 추적기 호실 오독은 2개뿐이다.
3. **평가 기준이 "사진 1장만 본다"이다.**
   - cjy 프롬프트는 이전 사진과의 관계를 평가에서 뺀다.
   - 추적기의 판단근거("문패 첫 자리로 3층이라고 추론", "VLM 장면 판단")와 목적지와의_관계("다른 층이라 돌아가야 함")는 지나온 기록에서 나온다.
   - 그래서 지금 사진에서 확인이 안 되면 감점된다. 맥락을 쓰는 방식에 불리한 기준이다.
4. 다음_행동 칸은 7-1절의 근사값을 채점한 것이다.

**정리**
- 실제 품질은 정답표 채점(7-2)과 안내 문장(4절)으로 본다. cjy 평가기 점수는 참고로만 둔다.
- 팀 평가 기준을 영상 길안내에 쓰려면 두 가지가 필요하다.
  - 평가 AI가 개수 검사에 자주 실패하므로 큰 평가 모델이 필요하다.
  - "이전 장면 기록을 근거로 한 판단"을 인정하는 항목이 있어야 한다. cjy와 의논할 거리다.
