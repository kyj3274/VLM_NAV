## 3. 검토 B: 구조 제안

### 3-1. 제로샷의 목표

> 처음 방문한 건물에서, 건물별 추가 학습이나 사전 지도 없이, 관찰한 표지판과 공간 정보를 이동 중 기억하면서 목적지를 찾는다.

- 이동 중에 기억을 쌓는 것은 제로샷에 어긋나지 않는다(사전 학습과 현장 기록은 다르다).
- 표지판도, 목적지도, 방문 기록도 없는 갈림길에서는 어떤 모델도 방향을 확정할 근거가 없다. 그때 필요한 것은 방향을 맞히는 능력이 아니라 **정보를 더 모으고, 탐색하고, 틀리면 되돌아오는 능력**이다.
- 목표: "낯선 건물에서 근거를 모으며 목적지를 찾고, 모를 때 틀린 확신을 하지 않는 시스템".

### 3-2. 지금 구조의 문제

| 지금 구조 | 문제 | 제안 |
|---|---|---|
| 호실 첫 자리로 층 추정 | B101, A-203, 1201에서 깨짐 | 호실 문자열과 층 정보를 따로 관리 |
| 번호가 목적지에 가까워지면 맞는 방향 | 번호 차이는 실제 거리와 다름 | 표지판, 복도 연결, 방문 기록을 먼저 보고 번호 추세는 보조 근거로 |
| OCR 결과를 글 목록으로만 전달 | 문패인지 안내도인지, 어느 문에 붙었는지가 사라짐 | 글자와 함께 위치, 출처 종류, 연결된 문, 관측 시각 보존 |
| 같은 번호가 반복되면 확신 증가 | 같은 안내도를 반복해서 보면 틀린 확신이 커짐 | 같은 물체를 다시 본 것과 새로운 근거를 구분 |
| 화면 왼쪽·오른쪽으로 공간 판단 | 휴대폰을 돌리면 화면 위치와 실제 벽이 달라짐 | 카메라 방향, 이동 상태, 물체 추적을 함께 사용 |
| 불확실하면 계속 직진 | 정보 없이 목적지에서 멀어질 수 있음 | 다시 관찰, 표지판 찾기, 되돌아가기 상태 추가 |
| 늦게 온 VLM 응답을 안내에 사용 | 촬영 때와 안내 때의 위치·방향이 다름 | 관측 시각과 상태를 확인해 오래된 행동 추천은 버림 |
| 지금 층과 첫 자리가 같은 문패만 인정 | 층을 처음에 틀리면 이후 맞는 문패까지 버림 | 층 판단을 고정하지 않고 근거로 다시 계산 |
| 문패 출력 `maxLength` 5 | 정규식은 `314-12`(6글자)도 허용 | 길이 제약 맞추기, 장기적으로 호실을 식별 문자열로 |

### 3-3. 인식과 판단 사이에 "공간 기억"을 넣기

1. **글자를 "어디에 붙은 어떤 정보인지"로 저장**
   - 문 옆 작은 문패의 314: 이 문이 314호라는 후보
   - 안내도의 314: 건물 안에 314호가 있다는 정보
   - "301–320 →" 표지판: 그 범위로 가는 방향 정보
   - 포스터 안의 314: 길안내 근거로 쓰지 않음
   - 안내도는 버리지 말고 별도 정보원으로 쓴다. 확장 순서는 방향 표지판 → 층별 시설 목록 → 평면 안내도.
2. **정밀한 지도 전에 간단한 연결 관계부터**
   - 엘리베이터 홀에서 복도로 들어왔다, 이 갈림길에서 한쪽은 확인했다, 그 끝에 목적지가 없었다, 다른 쪽은 아직 안 봤다, 이 문패는 어느 구간에서 봤다.
   - 비슷한 복도를 영상만으로 같은 곳이라고 합치지 않는다.
3. **안내한 것과 사용자가 실행한 것을 구분**
   - 안내 생성 → 전달 → 실행 대기 → 관측으로 확인 → 다음 판단

### 3-4. VLM에는 "다음 행동"보다 "관측의 의미"를

| 질문 | 출력 |
|---|---|
| 이 글자는 어디에 쓰여 있나 | 문패 / 방향표지 / 안내도 / 기타 / 모름 |
| 표지판의 어떤 글자와 화살표가 연결되나 | 목적지와 화살표의 대응 |
| 글자가 충분히 보이나 | 읽힘 / 일부 가림 / 흐림 / 모름 |
| 이 표지가 특정 문에 붙어 있나 | 연결된 문 후보 / 불명 |
| 두 관측이 같은 표지인가 | 같음 / 다름 / 판단 불가 |

출력 예:

```json
{"observation_id": "obs_104", "source_type": "DIRECTION_SIGN", "text": "301–320",
 "arrow_in_image": "RIGHT", "text_arrow_relation": "CLEAR", "readability": "CLEAR"}
```

- 이 결과는 "표지판에 오른쪽 화살표가 있다"는 관측이지, "오른쪽으로 도세요"라는 명령이 아니다.
- 모름(UNKNOWN)이 나오면 원인에 맞춰 다음 관찰을 고른다: 흐리면 다시 찍기, 잘렸으면 전체 보기, 연결이 불명확하면 주변 통로 확인.
- 표지판의 글자와 방향을 잇는 문제는 따로 연구되고 있다(*Sign Language*, 병원·쇼핑몰·교통시설 표지판).

### 3-5. 작은 모델을 판단하기 전에 실패 원인 나누기

같은 실패 사례를 네 조건으로 비교한다.

| 조건 | 확인하는 것 |
|---|---|
| 원본 전체 사진으로 읽기 | 시각 인식 능력 |
| 원본 해상도로 관심 영역만 읽기 | 축소·자르기에 의한 손실 |
| 사람이 확인한 정확한 관측을 주고 판단 | 추론·판단 능력 |
| 정확한 관측 + 방문 기록까지 주고 판단 | 공간 기억 부족의 영향 |

- 장면용 축소 사진과 글자용 원본 조각을 나눈다.
- "전체가 가장 선명한 사진"과 "문패가 가장 잘 읽히는 사진"은 다를 수 있다.

### 3-6. 빠른 처리와 느린 처리 분리

- 빠른 처리: 최신 프레임 받기, 물체 추적, 이동 상태, 기존 안내가 아직 맞는지.
- 느린 처리: 표지판 해석, 문패 재확인, 복잡한 장면 해석.
- 결과 반영: 촬영 시각, 관측 장소, 지금 상태를 비교한 뒤. 10초 전 사진에서 얻은 "314호 문패"는 기록에 남기고, "지금 오른쪽으로 도세요"는 버린다.
- 처리가 밀리면 오래된 프레임보다 최신 프레임을 먼저. 속도는 촬영부터 안내를 듣기까지로 잰다.

### 3-7. 평가 방식

| 용도 | 구성 |
|---|---|
| 개발용 | 지금 촬영한 건물과 경로 |
| 검증용 | 다른 동, 다른 번호 체계, 다른 복도 구조 |
| 최종 시험용 | 고칠 때 보지 않은 건물과 경로 |

시험 항목은 "314호 찾기"가 아니라 능력 단위로: 안내도 숫자를 현재 위치로 오인하지 않는가, 다른 번호 체계에서도 되는가, 표지판이 없을 때 탐색으로 바꾸는가, 확인한 통로를 반복하지 않는가, 잘못 간 뒤 돌아오는가, 목적지가 없을 때 적절히 끝내는가, 문 앞에서만 도착을 선언하는가.

### 3-8. 검토 B의 우선순위

| 순서 | 작업 | 기대 성과 |
|---|---|---|
| 1 | 문패·안내도·방향표지 분리, 호실과 층 분리 | 잘못된 층 변경과 가짜 문패 채택 감소 |
| 2 | 모름(UNKNOWN)과 다시 관찰 상태, 오래된 응답 폐기 | 근거 없는 직진·회전 안내 감소 |
| 3 | 문·표지 추적과 관측 출처 저장 | 반복 오독으로 확신이 커지는 문제 감소 |
| 4 | 방문 지점·미확인 갈래·복귀 경로 기억 | 탐색과 되돌아가기 |
| 5 | 표지판의 목적지–화살표 연결 해석 | 번호 추세 의존 감소 |
| 6 | 카메라 자세·이동 추정 보강 | 휴대폰 회전과 실제 이동 혼동 감소 |
| 함께 | 다른 건물 평가, 실제 이동 시험 | 일반화와 실제 도착률 확인 |

## 4. 종합 판단

**받아들일 것 (우리 기록과 맞음)**
- 행동은 규칙이, 모델은 관측의 의미만 (A7, B 3-4). 우리 측정과 같은 결론이다.
- VLM과 무거운 처리를 1초 처리에서 떼어 내고, 오래된 응답은 버린다 (A2, B 3-6).
- 글자의 출처(문패 / 안내도 / 표지판 / 포스터)를 먼저 가린다 (B 3-3). 11/16의 가짜 번호는 전부 출처 문제였다.
- 방향은 "차이가 줄었나" 대신 벽별로, 지나치지 않았는지까지 본다 (A4의 부호 검사, B 3-2).
- 층을 첫 자리로 고정하지 않는다 (B 3-2).
- 모를 때 "다시 보기 / 둘러보기 / 되돌아가기"를 행동으로 둔다 (B 3-1, 3-2).
- 개발·검증·시험 건물 분리 (B 3-7).

**그대로 받지 않을 것**
- A1 생각 토큰: 우리 기록에서는 생기지 않았다. 느림의 원인은 GPU 혼잡과 전송 경로다. `"think": false`만 명시한다.
- A4 홀짝 분리: 이 건물에서 이미 맞지 않는다. 벽 구분은 화면 위치 + 자이로(휴대폰 회전) + 깊이로 한다.
- A4의 "상자 높이 15%" 같은 고정 기준: 건물마다 달라서 학교에 맞춘 값이 될 위험이 있다.

**지금 가진 것으로 이어지는 부분**
- `nav_memory`(문패 믿음 점수, 사건 기록)가 공간 기억의 첫 단계다. 여기에 출처 종류, 연결된 문, 관측 시각, 벽 쪽을 더하면 B 3-3의 "관측 기록"이 된다.
- 깊이 모델(11/17 시험)은 A3의 원근 정렬과 B의 "어디에 붙은 정보인가"에 같이 쓸 수 있다.
- 자이로(검토 중)는 B 3-2의 "화면 위치와 실제 벽 혼동"을 직접 푼다.
- `tools/replay_sessions.py`는 회귀시험 도구로 그대로 쓴다.
