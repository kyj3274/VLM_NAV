## 2. 현재 구조

```
사진 ─┬─ YOLOE (0.14초) ── 문·계단·화장실·비상구표시·사람·상자 위치
      └─ OCR   (0.53초) ── 글자 + 위치 → 호실 후보 (3자리 숫자)
                    │
            [규칙, 시간 0]
            · 호실: 점수 0.5 이상 + 사진 안 첫 자리 다수결, 큰 글자(가까운) 순 정렬
            · 엘리베이터: 큰 문 위에 층 숫자(OCR) → 확정
            · 방향: 상자 위치로 계산 (왼쪽 1/3=11시, 가운데=12시, 오른쪽=1시)
                    │
            [VLM qwen3-vl, 사진당 1번, 필요한 질문만 묶음]
            · R 호실 후보 조각 → 예/아니요/판단 불가
            · O 물체 조각(여백 1.8배) → 무엇인지 고르기
            · S 비상구 표지 조각 → 화살표 방향
            · B (시험 중) 큰 문 양옆 벽 → 호출 버튼 있나
```

**역할 정리**
- **OCR이 중심**: 호실·공간 이름은 OCR이 읽고, VLM은 OCR 후보를 확인만 한다.
- **YOLOE는 "어디를 볼지"**: 글자 없는 표지(비상구, 화장실 그림)와 장애물을 찾고, VLM에 보낼 조각 위치를 정한다. 방향은 상자 위치로 계산한다.
- **VLM은 "그게 뭔지"**: 만들지 않고 고르기만 한다(객관식, schema로 허용 값 제한).

## 3. 물체 조각 분류 (10/20)

YOLOE가 찾은 물체를 잘라서 VLM에게 무엇인지 고르게 했다. 기존 엘리베이터 질문(E)을 이 질문(O)으로 바꾸고, 호실(R)·화살표(S)와 같은 호출에 묶었다. 상자는 큰 것(가까운 것)부터 최대 5개.

**평가용 117장**

| | 기존 최종 (D3h) | ① 딱 맞게 | **② 여백 1.8배** | ③ 여백 + 전체 사진 |
|---|---|---|---|---|
| 호실 F1 / 가까운 호실 | 89 / 23/23 | 89 / 23/23 | **90** / 23/23 | 89 / 23/23 |
| 랜드마크 5종 F1 | **74** | 69 | 73 | 73 |
| └ 문 | 93 | 86 | 91 | 91 |
| └ **화장실** | 30 | 40 | **64** | 50 |
| └ 비상구표시 | 59 | 64 | 63 | 65 |
| └ 엘리베이터 | **25** | 18 | 19 | 22 |
| 시간 중앙값 | 3.9초 | 3.4초 | **3.5초** | 3.9초 |

- **② 여백 1.8배가 가장 좋다.** 딱 맞게 자르면 맥락이 부족하고, 전체 사진을 더 넣어도 이득이 없다.
- **화장실이 두 배**: YOLOE가 잘못 붙인 화장실을 VLM이 조각을 보고 바로잡았다.
- **엘리베이터는 나빠졌다**: VLM이 일반 철문 조각을 엘리베이터로 고름(엘리베이터 없는 사진 약 40장). **문 생김새로는 YOLOE·Grounding DINO·qwen3-vl 모두 구분 못 함.**
- 얇은 조각(사진 끝 2% 폭)은 Ollama가 오류(500)를 냄 → 조각 비율을 3:1 이내로 넓히고 사진 안쪽으로 밀어서 해결.

## 4. 엘리베이터 = 호출 버튼으로 판단 (10/23)

엘리베이터와 일반 철문의 결정적 차이는 **옆 벽의 위/아래 호출 버튼**(우리 아이디어).

- **YOLOE로 버튼 패널 직접 찾기**: 실패. 엘리베이터 사진 15장 중 7장을 찾을 때 오탐 42장(기준 0.1). 작은 패널은 글 표현만으로 못 찾음.
- **VLM으로 문 양옆 확인 (B 질문)**: 큰 문 최대 2개의 양옆 벽(문 높이 20~95% 구간)을 잘라 왼쪽|오른쪽으로 붙여 "위/아래 화살표 호출 버튼이 보이나?" 질문.
  - 처음엔 25~80% 구간이라 버튼이 잘렸음(우리 건물 버튼은 낮게 달림) → 20~95%로 수정.
  - 엘리베이터는 **OCR 층 숫자 또는 버튼 '예'일 때만** 확정. VLM이 문 조각을 "엘리베이터"로 고른 답은 "문"으로 처리.

**176장, 엘리베이터 사진 15장**

| 엘리베이터 판단 | 찾음 | 오탐 | P / R |
|---|---|---|---|
| 기존 최종 (VLM이 문을 보고) | 8 | 14 | 36% / 53% |
| ② 물체 조각 (VLM이 조각을 보고) | 12 | 40 | 23% / 80% |
| **② + 버튼 확인** | 6 | **8** | **43%** / 40% |
| (미리 계산) 버튼은 VLM이 엘리베이터로 고른 문에만 | 6 | 7 | 46% / 40% |

| 평가용 117장 | 기존 최종 | ② 여백 | ② + 버튼 |
|---|---|---|---|
| 랜드마크 5종 F1 | 74 | 73 | **76** |
| 화장실 / 비상구표시 | 30 / 59 | **64 / 63** | 52 / 61 |
| 시간 중앙값 (176장) | 3.8초 | 3.5초 | **5.0초** (86장이 5초 초과) |

- 버튼 질문으로 **오탐이 크게 줄었다.** "엘리베이터인가?"보다 "버튼이 보이나?"가 훨씬 확실한 질문.
- **놓침 9장**: ① YOLOE가 고른 "가장 큰 문"이 엘리베이터가 아님(4F_046), ② 멀리서 찍혀 버튼이 너무 작음(5F_024, 5F_026).
- **버튼을 모든 큰 문에 물어서(155장) 느려지고**, 조각이 많아져 화장실·비상구 판단이 흐려짐.
- **다음 안 (아직 실행 안 함)**: 1차 호출에서 VLM이 "엘리베이터"로 고른 **그 문의 양옆만** 2차로 버튼 확인. 묻는 문이 276 → 약 47로 줄고, 엉뚱한 문을 확인하던 문제도 해결될 것으로 예상.
- 주의: 엘리베이터 사진이 15장(평가용 7장)뿐이라 숫자는 경향만 본다.

## 6. 프롬프트 변화

### 6-1. 바뀐 흐름

| 시기 | VLM 역할 | 프롬프트 방식 | 결과 |
|---|---|---|---|
| p2 (10/17) | **전부 생성** (호실·층·공간·랜드마크·방향) | 긴 설명 + 랜드마크 23개 목록 + 예시 `"999"` | 호실 지어내기(`999`, `101…`), 목록 골라 담기, 문패를 화살표로 착각 |
| 2단계 (10/19) | 확인 + 추가 읽기 | OCR·YOLOE 결과를 글로 주고 엘리베이터/화살표/추가 호실 질문 | 화살표 오탐 0, 엘리베이터 개선. VLM이 호출 134장으로 과다 |
| **D3h (10/20)** | **고르기만** | 후보에 번호(R1, E1, S1) → 예/아니요/판단 불가, **후보 조각을 잘라서** 보여 줌, 이유별 질문만 묶음, 한국어, 근거 없이 답만 | 가까운 호실 23/23, 호실 F1 89 |
| **O (10/20)** | 물체 조각 분류 | YOLOE 조각(여백 1.8배) → 7개 선택지 중 고르기 | 화장실 30 → 64 |
| **B (10/23, 시험 중)** | 버튼 유무 | 문 양옆 벽 조각 → 예/아니요/판단 불가 | 엘리베이터 오탐 40 → 8 |

**실험으로 확인된 프롬프트 원칙**
1. **만들게 하지 말고 고르게 한다** (객관식 + schema enum). 지어내기가 구조적으로 막힌다.
2. **글로 설명하지 말고 잘라서 보여 준다.** 전체 사진만 주면 VLM이 먼 문패를 못 읽고 "아니요"라고 답한다. 조각을 주면 실제로 확인한다.
3. **"이게 X인가?"보다 "X에만 있는 단서가 보이나?"** — 엘리베이터 → 호출 버튼.
4. **한국어, 답만.** 영어는 "예" 쪽으로 쏠렸고, 근거 필드는 근거와 답이 어긋나 정확도를 낮췄다(`docs/exp/04`).
5. **구체적 숫자 예시는 넣지 않는다** (`410`, `999` 베끼기).
6. 번호 상자 그리기(Set-of-Mark)는 이번 데이터에서 효과 없음 — 오히려 가까운 정답을 버림.
7. qwen3-vl은 "판단 불가"를 거의 쓰지 않는다(0/37). 신뢰도 단계에서 따로 다뤄야 함.

### 6-2. 현재 프롬프트 원문 (`src/exp_d_vlm.py`, `src/exp_obj_vlm.py`)

공통 머리말
```
시각장애인 실내 길안내를 위해 사진 속 후보를 확인합니다. 아래 질문에만 JSON으로 답하세요.
확실하지 않으면 추측하지 말고 '판단 불가'로 답하세요.
이미지들은 차례대로 R1, O1, …, S1, B1 부분을 원본 사진에서 확대한 것입니다.
```

R (호실 후보)
```
[호실 번호] 글자 인식기가 아래 숫자를 읽었습니다. 각 후보가 문패(방 이름표)에 적힌 호실 번호이고
사진 속 숫자가 후보와 정확히 같으면 '예', 문패가 아니거나 숫자가 다르면 '아니요'.
- R1: "404" — 사진 왼쪽 위 (가로 12%, 세로 12% 위치)
```

O (물체 조각) — 답: 문 / 엘리베이터 / 계단 입구 / 화장실 / 비상구 표시 / 기타 / 판단 불가
```
[물체] 물체 탐지기가 찾은 부분입니다. 각 O 조각의 가운데에 있는 것을 하나 고르세요.
엘리베이터=가운데가 갈라지는 금속 문(호출 버튼이나 층 표시가 함께 보이는 경우가 많음),
문=방이나 복도의 일반 출입문, 계단 입구=계단이나 계단실 입구, 화장실=화장실 표지나 입구,
비상구 표시=초록색 피난 유도 표지. 해당하지 않으면 '기타', 확실하지 않으면 '판단 불가'.
```

S (화살표) — 답: 12시~11시 중 최대 2개
```
[화살표] 사진 속 표지판이나 유도등에 화살표 모양이 그려져 있으면, 화살표가 가리키는 방향을
시계 방향으로 답하세요 (12시=앞/위쪽, 3시=오른쪽, 9시=왼쪽). 화살표 모양이 없으면 빈 배열.
```

B (호출 버튼, 시험 중)
```
[호출 버튼] 각 B 조각은 큰 문의 양옆 벽을 확대해 왼쪽|오른쪽으로 붙인 것입니다.
벽에 위쪽·아래쪽 화살표가 있는 호출 버튼(엘리베이터를 부르는 버튼)이 보이면 '예',
없으면 '아니요', 확실하지 않으면 '판단 불가'.
전등 스위치, 화재 경보기, 카드 단말기 같은 다른 장치는 '아니요'.
```
> B의 마지막 문장은 "헷갈리는 것 설명"이라 앞서 빼기로 한 5번 방식과 비슷하다. 다만 건물 특화가 아닌 일반 장치라 넣었다. 빼고 비교해 볼 필요가 있다.

설정: temperature 0, seed 42, num_predict 96~128, schema로 답 형식 고정, Ollama 0.24.0(GPU 7).
