# 01. 실험 A — OCR 입력 설정 (2026-10-20)

## 무엇을 했나
- `src/kyj/exp_a_ocr.py` (서버 같은 경로): YOLOE는 현재 설정(yoloe-11l, 3A 평균, imgsz 1280, 기준 0.15) 그대로 한 번만 실행해서 `exp_a_yoloe.jsonl`로 저장하고, OCR 설정만 바꿔 176장을 돌렸다. 합치기 규칙은 `pipeline.combine`을 그대로 썼다(점수 0.5 이상 글자).
- 인식 모델은 모든 설정에서 `korean_PP-OCRv5_mobile_rec`로 고정했다. GPU 3에서 `gpu_lock.sh 3`로 감싸 실행했다. 예열 2회 뒤 시간을 쟀다.
- 시간 = YOLOE + OCR(축소 포함). 사진 읽기(디코딩)는 기존 1단계와 같이 뺐고 `load_seconds`에 따로 남겼다.
- 설정 (m = PP-OCRv5_mobile_det, s = PP-OCRv5_server_det, 숫자 = OCR 입력 긴 변):
  - 해상도: 1024 / 2048 / 2560 / 3072 / 원본(`orig`, det `max_side_limit` 6000으로 사실상 축소 없음)
  - `*orig_det2048`: 입력은 원본 그대로 두고(인식 조각은 고해상도), 위치 찾기만 긴 변 2048
  - det 파라미터: `m2048_box05` (box_thresh 0.6→0.5), `m2048_th02` (thresh 0.3→0.2, box 0.5)
- `m2048`은 기존 `pipeline_stage1.jsonl`과 176장 모두 rooms/landmarks가 같다. 기준선이 그대로 재현됐다.
- 참고: `text_det_max_side_limit`는 PaddleOCR 생성자와 `predict()`가 받지 않는다. 그래서 내부 `ocr.paddlex_pipeline.predict`를 직접 호출했다.

## 기준 편향 보정 (중요)
기준 v2의 호실 후보는 **m2048 OCR 결과에서만** 만들었다. 그래서 다른 설정이 새로 맞게 읽은 문패도 틀림으로 센다. dev에서 기준에 없는 호실 후보 41곳을 원본에서 잘라 눈으로 확인했다(에이전트 판정이며 사람이 확인하지 않음). 실제 문패 7개를 보정 정답에 넣었다: `outputs/kyj/exp_a_extra_rooms.json`.
- 4F_046 409, 5F_007 530, **5F_013 510(가까움, 흐린 큰 문패)**, 5F_019 501, 5F_025 505, 5F_040 533·501. 4F_067 412는 판독이 불확실해 채점에서 뺐다.
- 보정 채점: `python3 src/kyj/score_v2_adj.py --split dev ...` (score_v2와 같은 사용법).
- 나머지 새 후보(3F_007 311→실제 310, 289, 212=보안업체 스티커, 808/806/800/831/833/404/464=5xx 오독 등)는 모두 오독이다. m2560/s2560에서 나온 일부 새 후보(499, 811, 425, 413, 131, 512, 748, 200)는 crop을 보지 않았고, 위치상 오독으로 보고 정답에 넣지 않았다.

## 배운 점
- **가까운 호실은 mobile_det 1024~3072 어디서나 다 읽는다.** 해상도를 올려 늘어나는 것은 먼 문패다. 그런데 먼 작은 글자는 5xx→8xx/6xx처럼 첫 자리를 잘못 읽는 경우가 많아 정밀도가 떨어진다(m3072 틀림 6→15).
- **server_det는 2048에서만 쓸 만하다.** 2560 이상에서는 큰(가까운) 문패를 놓치기 시작하고(s3072 가까운 4/6), 원본에서는 거의 못 찾는다(sorig 0/6). 큰 글자에서 위치 모델의 수용 영역이 모자라는 것으로 보인다.
- 1024는 빠르지만(0.31초) 먼 호실 재현율이 절반으로 준다.
- det 파라미터: box_thresh 0.5는 결과가 같았고, thresh 0.2는 더 나빴다(오독 증가). 기본값을 유지한다.
- 원본 입력에 det만 2048로 제한하면(`*orig_det2048`) 정밀도는 좋다. 하지만 5층 큰 사진에서 3~4초가 걸려 예산을 넘긴다(인식 조각을 큰 원본에서 자르고 축소하는 비용).
- 랜드마크는 YOLOE가 같아서 거의 변화가 없다(s2048은 엘리베이터 위 층 숫자를 못 읽어 엘리베이터 F1 22→0).

## 결론
- **기본 설정은 m2048(현재 설정)을 유지한다.** 공식 기준과 보정 기준 모두에서 정밀도가 가장 높고(84, 층 규칙을 쓰면 94), 0.63초로 VLM 시간을 충분히 남긴다. det 파라미터도 기본값 그대로 둔다.
- 대안은 s2048이다. 보정 기준에서 가까운 호실이 7/7(5F_013 510 하나 차이)이지만 정밀도는 4점 낮고 0.2초 느리다. 이 하나의 차이는 흐린 문패에 대한 에이전트 판정에 기대고 있어서 기본값을 바꾸지 않았다. 실험 B에서 층 일관성 같은 규칙을 넣으면 m3072·s2048의 이점이 커질 수 있으므로 이 두 원자료도 함께 넘긴다.
- test는 채점하지 않았다.
