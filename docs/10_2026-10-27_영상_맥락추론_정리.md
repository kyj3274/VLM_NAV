# 10. 영상으로 맥락 추론·길안내 시험 (2026-10-26~27)

> **목표**: 사진 1장 단위를 넘어, **걸어가는 영상**에서 "지금 어디쯤이고 다음에 뭘 해야 하나"를 판단해 시각장애인이 말만 듣고 목적지(314호)까지 갈 수 있게 안내하는 것.
> - 예: 문을 열고 들어가세요 → 앞에 엘리베이터 → 3층을 누르세요 → 내려서 오른쪽 → 목적지가 보입니다 약 몇 m → 도착했습니다
>
> **고정 조건**: VLM은 qwen3-vl:4b-instruct, 정확도 우선, 판단 1번당 5초 이내(중앙값).
> **서버**: YOLOE·OCR은 GPU 3, VLM은 GPU 7 Ollama 0.24.0(포트 11436). 결과 원본은 `outputs/kyj/video/`, Mac 복사본은 `data/video/`.

## 1. 요약

- **VLM에게 매 프레임 상황을 서술시키는 방식은 쓸 수 없었다.** 느리고(중앙값 4.6~5.1초), 엘리베이터 위치 표시 "5"를 "5층"으로 착각한 뒤 끝까지 유지했다.
- **규칙 추적기 + 애매할 때만 프레임 늘리기 + VLM은 마지막 수단**으로 바꿨다.
  - 314호 경로에서 VLM 호출이 87번에서 4~7번으로 줄었고, 초당 처리 중앙값은 0.9~2.3초다.
  - 3층 경로에서는 314호를 왼쪽 약 2 m에서 찾았다. 4층에 잘못 내린 경로에서는 "엘리베이터로 돌아가 3층을 누르세요"라고 안내했다.
- **"VLM이 정말 추론했나?"를 따로 평가했다** (판단 지점 17개, 정답표를 먼저 만듦).
  - VLM에게 다음 행동까지 한 번에 고르게 하면 17개 중 0~5개만 맞았다. 4B든 7B·12B든 같았다.
  - 질문을 한 칸짜리 객관식으로 쪼개면(c 방식) **층 17/17, 목적지 층인가 17/17**을 맞혔다. 다음 행동은 규칙으로 조합해 14/17이 맞았다.
  - 하지만 "가까워지나/멀어지나"는 9/17로, 거의 한 답만 반복했다.
  - **결론**: 4B VLM은 "한 단계 판단"은 하지만 "여러 단계 조합"은 못 한다. 형식은 우리가 정하고, VLM은 쪼갠 질문에만 답한다.
- **qwen3.5:4b도 시험했지만 qwen3-vl보다 나은 조건이 없어 버렸다** (5절).
- **가장 큰 남은 문제는 방향 판단이다** (6절). 프레임을 직접 확인해 보니 번호는 **벽마다 따로 순서대로** 붙어 있었다 (왼쪽 317 → 316 → 315 → 314 → 313, 오른쪽 309 → 307). 지금 규칙은 양쪽 벽과 멀리 있는 문패, OCR 오독을 한 줄로 섞어서 번호가 뒤죽박죽처럼 보였다.
- **프레임별 정답표를 만들었다** (9절). 1단계(YOLOE+OCR)를 1초 1장으로 채점하면 영상 속 호실은 33개 중 18개만 읽고, 엘리베이터 탐지는 거의 안 된다.

## 3. 시도한 방식과 결과

### 3-1. VLM이 매 프레임 상황 서술 (실험 A/B)

| 실험 | 내용 | 중앙값 | 문제 |
|---|---|---|---|
| A0 | 사진 1장 → 장면 종류, 보이는 길, 문, 엘리베이터 등 JSON | 5.1초 | 보이는 길이 대부분 "모름" |
| A1 | A0 + 1단계(OCR·YOLOE) 단서를 글로 같이 줌 | 5.0초 | 단서를 거의 그대로 베낌 |
| B | 이전 상태 + 새 사진 → 현재 층·위치 갱신 | 4.6초 | 엘리베이터 위 위치 표시 "5"를 **5층**으로 읽고 끝까지 유지 |

- 87장 모두 VLM을 부르면 영상 1개에 4분 이상 걸린다. 실시간 안내에 맞지 않는다.

### 3-2. 규칙 추적기 + 애매한 순간만 촘촘히 + VLM 마지막 수단 (`video_tracker.py`)

```
1초마다 1장 ─ YOLOE + OCR ─▶ [1층] 규칙 추적기
                                층 = 호실 첫 자리, 진행 = 가까운 문패 번호 변화, 단서 없으면 확신 감소
               애매하면 ──────▶ [2층] 그 1초의 8장을 모두 보고 투표 (2번 이상 보이거나 점수 0.9 이상만 인정)
                                애매 = 흐림(선명도 <30), 깨진 숫자, 숫자 없는 한글 문패, OCR 점수 0.3~0.9, 목적지 ±2
               그래도 모르면 ─▶ [3층] VLM (사건이 있을 때만)
                                경로 시작, 엘리베이터 하차, 엘리베이터 후보 2초 연속, 단서 없음 10/20/30초,
                                층 충돌 2초 연속, 가까운 문패를 못 읽음
```

- 거리 = 0.72 × 2.1 m ÷ 문 상자 높이 비율 (문 높이 2.1 m, 화각 약 70° 가정). 문이 화면 끝에 닿으면 1.5 m. 2 m 이내면 도착.
- 안내 문장은 정해진 틀(템플릿)에 상태를 끼워 만든다.

| 경로 | VLM 호출 | 초당 처리 중앙값 | 안내 결과 |
|---|---|---|---|
| A (3층, 314호) | 4~5번 (매 프레임이면 87번) | 0.9~2.3초 | 유리문 → 엘리베이터(15초) → 3층 확인 → "314호가 왼쪽에 보입니다, 약 2 m" |
| B (4층 하차) | 4~5번 | 비슷 | 410호 → "4층입니다. 엘리베이터로 돌아가 3층을 누르세요" |

처음 버전에서 고친 오류:

| 오류 | 원인 | 고침 |
|---|---|---|
| 9초에 이른 "엘리베이터 타세요" | 단서 없음 호출에서 VLM이 엘리베이터 있다고 답함 | 장면이 엘리베이터 홀이고 후보가 2초 연속일 때만 |
| 층이 1층으로 바뀜 | OCR이 `118`로 잘못 읽음 | 층 충돌은 2초 연속일 때만 인정 |

| 마지막 314호 놓침 | 1초 1장에서 흐림 | 목적지 ±2 번호면 8장 모두 확인 |
| 방향·거리 빈칸 | 다른 프레임 값을 씀 | 목적지를 읽은 그 프레임에서 계산 |

데모 화면: `data/video/demo_results_guide_314_1_2b.html`, `..._2a.html` (초별 프레임, 판단, 안내 문장).

### 3-3. VLM이 정말 추론했나? (판단 지점 평가, `video_reason.py`)

솔직히 3-2의 안내는 **대부분 규칙과 템플릿이 만든 것**이고 VLM은 장면 종류와 층 확인 정도만 했다. 그래서 VLM 혼자 얼마나 판단하는지 따로 쟀다.

- 정답표 `data/video/checkpoints.json`: 판단 지점 17개 (경로 A 10개, B 4개, 가상 목적지 318호 경로 C 3개). 모델 결과를 보기 전에 프레임을 보고 확정했다.
- 칸: 현재 층, 목적지 층인가, 진행(가까워짐/멀어짐), 다음 행동.

| 조건 | 다음 행동 맞음 (/17) | 비고 |
|---|---|---|
| ① 규칙만 | **15** | |
| ② VLM: 사진 + 지금까지 기록 | 0 | |
| ③ VLM: 기록만 (사진 없이) | 3 | |
| ④ ② + 일반 상식 힌트 | 0 | |
| a 선택지 순서 섞기 | 0 / 3 | 위치 편향은 아님 |
| b/e 답 전에 생각 칸 | 3 / 3 | 생각해도 안 나아짐 |
| **c 질문 쪼개기** | **14** | 층 17/17, 목적지 층 17/17, 진행 9/17 |
| d qwen2.5vl 7B | 3 / 5 | 큰 모델도 비슷 |
| d gemma3 12B | 4 / 5 | |

- **c 방식**: VLM에게 "목적지는 몇 층?", "지금 몇 층?", "가까워지나?", "장면 종류?"를 각각 한 칸 객관식으로 묻고, 다음 행동은 규칙이 조합한다.
- c의 14개는 규칙 조합 덕이 크다. VLM이 진짜 맞힌 것은 층과 목적지 층이다. 진행은 "가까워짐"만 거의 반복했다.

### 3-4. c 방식을 추적기에 넣은 결과

- 입구 "앞에 문이 있습니다. 문을 열고 들어가세요" → 15초 엘리베이터 → 317호에서 VLM이 "3층" → "3층이 맞습니다" → 314호 왼쪽 약 2 m.

- VLM 6~7번, 중앙값 1.2초.
- **틀린 것**: 목적지를 318호로 바꾸면 반대로 가는데도 "315호 … 방향이 맞습니다"라고 한다 (6절).

## 4. 왜 추론을 못 하나

- 모델 크기 문제만은 아니다. 7B·12B도 한 번에 고르게 하면 3~5개였다.
- 한 질문에 "층 읽기 → 목적지와 비교 → 진행 판단 → 행동 고르기"가 겹치면 중간 단계를 건너뛰고 그럴듯한 답(대개 "직진")을 고른다.
- 한 단계씩 물으면 층 판단은 다 맞는다. → **형식(단계)은 우리가 정하고, VLM은 단계마다 고르기만** 하는 것이 맞다.

## 6. 방향 판단 문제 (가장 큰 남은 문제)

### 6-1. 지금 규칙

가까운 문패 번호가 목적지 번호에 가까워지면 "방향이 맞습니다", 3번 연속 멀어지면 "뒤로 돌아가세요". **번호가 복도를 따라 순서대로 바뀐다고 가정**한 규칙이다.

### 6-2. 실제 복도 (프레임을 원본 크기로 직접 확인)

> 처음(10/27 오전)에는 OCR 결과의 화면 위치만 보고 "같은 왼쪽 벽에 317 → 316 → 315 → 307 → 313 → 314가 섞여 있다"고 적었다. **틀린 판단이었다.** 프레임을 직접 보니 아래와 같다.

| 초 | 실제 문패 | 실제 벽 | OCR이 읽은 것 | 비고 |
|---|---|---|---|---|
| 4~6 | 317 | 왼쪽 | 317 (4초는 못 읽음) | |
| 6~8 | 316 | 왼쪽 | 6초에 **310**으로 오독 | |
| 7~10 | 309 | **오른쪽** | 못 읽음, 10초에 **305**로 오독 | 문패가 비스듬함 |
| 15~17 | 315 | 왼쪽 | 315 | |
| 18~23 | 307 | **오른쪽** | 307 (20~23초) | 20~23초는 카메라가 오른쪽 벽을 정면으로 봐서, 화면상으로는 왼쪽에 찍힘 |
| 25~27 | 314 | 왼쪽 | 27초에만 읽음 | 25초부터 왼쪽 맨 앞 문이 314호인데 문패가 옆을 향해 안 보임 |
| 25~27 | 313 | 왼쪽 (314 너머) | 313 | 정면을 향한 문패라 멀리서도 먼저 읽힘 |

- **왼쪽 벽: 317 → 316 → 315 → 314 → 313**, **오른쪽 벽: 309 → 307**. 벽마다 번호가 걷는 방향으로 줄어든다. 4층(경로 B)도 왼쪽 410 → 412 → 413, 오른쪽 407로 같은 모양이다.
- 사용자 지적대로 **양쪽 벽에 방이 있어서** 번호가 섞여 보였다. 뒤죽박죽처럼 보인 원인은 셋이다.
  1. 양쪽 벽 번호를 한 줄로 섞었다.
  2. OCR 오독(316 → 310, 309 → 305, 413 → 418)
  3. 읽히는 순서와 실제 순서가 다르다. 정면을 향한 먼 문패(313)가 옆을 향한 가까운 문패(314)보다 먼저 읽힌다.
- 왼쪽 벽에 317, 316, 315가 같이 있으니 **"홀수끼리, 짝수끼리 비교"는 틀린 해결책**이다.
- 화면 위치(x)만으로는 벽을 알 수 없다. 카메라를 돌리면 오른쪽 벽 문패도 화면 왼쪽에 찍힌다 (20~23초).
- 314호 경로가 맞게 안내된 것은 운이 좋았기 때문이다. 318호 경로에서 틀렸다.
- 단, 영상 2개, 복도 2개에서 본 것이라 다른 층·건물에서도 벽마다 순서대로라고 단정할 수는 없다.

### 6-3. 생각해 볼 방향 (아직 정하지 않음)

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ⓪ 벽별로 따로 추세 보기 | 문패를 벽(왼쪽/오른쪽)별로 나누고, 가까이 와서 확실히 읽은 문패만 써서 벽마다 번호가 늘어나는지/줄어드는지 본다. 벽 구분은 화면 위치가 아니라 물체 추적과 카메라 방향으로 | 지도 없이 됨. 이번 영상에서는 맞음 | 벽 구분이 어려움. 순서대로가 아닌 건물에서는 틀림. 그때는 ①로 |
| ① 번호로 방향을 말하지 않음 | "아직 목적지 문패가 안 보입니다, 계속 가세요"만 말하고, 지나간 문패를 기록. 복도 끝에 닿으면 되돌아가기 | 거짓 안내를 하지 않음. 지도 없이도 됨 | 최악이면 복도를 다 걸어야 함 |
| ② 층별 방 순서표 | 층마다 엘리베이터에서 각 방향으로 나오는 방 순서와 벽 쪽을 한 번 적어 둠 | 가장 정확. "내려서 오른쪽"을 말할 수 있음 | 건물마다 미리 조사해야 함 (제로샷이 아님) |
| ③ 건물 안의 안내 표지 읽기 | 층 안내도, "301~310 →" 같은 표지를 OCR로 읽어 방향 결정 | 제로샷 유지. 사람도 이렇게 찾음 | 표지가 있는 곳에서만 됨. 이번 영상에서는 확인 못 함 |
| ④ 확신도와 함께 말하기 | 번호 추세는 참고만 하고 "확실하지 않습니다"를 붙임 | 구현 쉬움 | 시각장애인에게 애매한 말은 도움이 덜 됨 |

- 지금 판단: **⓪을 먼저 시험하고, 확신이 없으면 ①로 물러난다.** ②(안내도로 순서표 만들기)는 나중으로 미룬다 (10/27 우리 결정). 팀 논의가 필요하다.
