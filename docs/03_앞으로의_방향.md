# 앞으로의 방향

2026-10-04 기준. 위에서부터 우선순위 순.

## 1. 팀에 바로 공유할 것

- [ ] **GPU로 도는 Ollama가 있다**: cjy가 띄운 `127.0.0.1:11435` (Ollama 0.24.0, GPU 6번)
  - 기존 `11434`(0.35.1)는 드라이버 문제로 CPU 전용
  - 앞으로 모델 비교는 전부 GPU 쪽으로 통일하자고 제안
- [ ] **Ollama를 재시작하면 다른 사람 실험이 끊긴다**: 오늘 kyj 4층 실행 10장이 이 때문에 실패. 재시작 전에 단톡에 공지하기
- [ ] **3층 사진 101장 중 50장이 중복** (같은 파일). 3층 결과의 성공 수와 평균이 부풀려져 있음
- [ ] **프롬프트 예시 베끼기**: `예: '410호, 강의실, EXIT, 비상구'` 때문에 3·5층 사진에서도 `410호`가 나옴 (gemma3:4b에서 41건)
- [ ] **temperature 미고정**: 같은 모델(qwen3-vl)인데 kyj와 cjy 결과가 25장 중 14장 다름. 팀 템플릿에 `"options": {"temperature": 0, "seed": 42}` 추가 제안
- [ ] **qwen3-vl:4b 담당 정리**: cjy와 kyj가 같은 모델을 돌림. 누가 맡을지 정하기

## 2. 실험 조건 다시 맞추기

| 항목 | 지금 | 제안 |
|---|---|---|
| 실행 장치 | CPU와 GPU가 섞임 | 모두 GPU(11435) |
| Ollama 버전 | 0.24.0 / 0.34.4 / 0.35.1 섞임 | GPU용 0.24.0으로 통일 |
| temperature | kyj만 고정 | 모두 0, seed 42 |
| 답 길이 | 제한 없음 → 반복하다 60초 초과 | `num_predict` 제한 (예: 256) |
| 3층 사진 | 101장 (중복 50) | 중복 제거한 51장 기준으로 집계 |
| 프롬프트 예시 | `410호, 강의실, EXIT, 비상구` | 원본 유지 버전 + 예시를 실제 데이터에 없는 값으로 바꾼 버전 둘 다 |

`run_task.py`에 필요한 수정 (Mac에서 작성 → 승인 후 서버 반영):
- [ ] `--ollama-url` 옵션 (GPU 서버 `http://127.0.0.1:11435` 선택)
- [ ] `num_predict` 제한
- [ ] 중복 사진 건너뛰기 옵션

## 3. GPU로 다시 돌리기 (kyj)
- [ ] cjy와 GPU 사용 시간 조율 (`11435`는 동시에 1개 요청만 처리)
- [ ] qwen3-vl:4b-instruct, signs, 3·4·5층 176장 (중복 제외)
  - GPU 응답 시간 중앙값이 2.7초라 **10분 안팎** 예상
- [ ] 끝나면 `review/`에 결과 추가해서 검수 페이지에 반영

## 4. 정답(GT) 만들기
- [ ] 검수 페이지(`review/review.html`)로 176장 정답 입력
  - 5명이 나누면 1인당 약 35장. 예: 3층 51장 / 4층 81장(2명) / 5층 44장
  - 입력 기준 먼저 합의: 포스터 속 작은 글씨까지 넣을지, 표지판과 호실 번호만 넣을지
  - CSV로 모아서 "CSV 불러오기"로 합치기
- [ ] 정답이 생기면 모델별 정밀도·재현율·F1을 표로 정리

## 6. 길게 보면
- 지금은 학습이 아니라 **평가(baseline)** 단계. 모델 자체는 바뀌지 않음
