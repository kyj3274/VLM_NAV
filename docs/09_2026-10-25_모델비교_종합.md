### 1-2. 핵심
- **구조를 바꿨다.** VLM이 사진 전체를 보고 글자를 "쓰는" 방식에서, **OCR이 읽고 YOLOE가 위치를 찾고, VLM은 잘라낸 조각을 보고 "고르기"만** 하는 방식으로 바꿨다.
- **호실이 가장 크게 좋아졌다.** 평가용 117장에서 F1 32 → 90, 가까운 호실 11/23 → 23/23이다.
- **VLM 모델은 qwen3-vl 4B로 정했다.** qwen2.5vl 7B는 정확도가 비슷한데 5.9~6.5초로 5초 기준을 넘는다.
- **탐지 모델은 YOLOE-11l로 정했다.** Grounding DINO 계열은 재현율은 높지만 오탐이 많고 4~6배 느리다.
- **남은 약점은 층 표시, 계단, 엘리베이터, 공간 이름 정리**다.

## 3. 항목별 결과와 시도

### 3-1. 호실

**OCR 입력 (실험 A, dev 59장)**

| 설정 | 호실 P / R / F1 | 맞음 / 틀림 / 놓침 | 가까운 호실 | 1단계 시간 |
|---|---|---|---|---|
| mobile 1024 | 81 / 45 / 58 | 17 / 4 / 21 | 6/6 | 0.31초 |
| **mobile 2048 (채택)** | **84 / 84 / 84** | 32 / 6 / 6 | 6/6 | 0.63초 |
| mobile 3072 | 68 / 84 / 75 | 32 / 15 / 6 | 6/6 | 1.17초 |
| mobile 원본 | 64 / 84 / 73 | 32 / 18 / 6 | 6/6 | 2.38초 |
| server 2048 | 76 / 82 / 78 | 31 / 10 / 7 | 6/6 | 0.81초 |
| server 원본 | 71 / 13 / 22 | 5 / 2 / 33 | **0/6** | 1.60초 |

- 가까운 호실은 mobile 1024~3072 어디서나 다 읽는다.
- 해상도를 올리면 먼 문패를 더 읽는다. 대신 첫 자리 오독(5xx → 8xx)이 늘어 정밀도가 떨어진다.
- server 위치 모델은 큰 입력에서 가까운 큰 글자를 놓친다.

**호실 규칙 (실험 B·C, dev 59장)**

| 규칙 | P / R / F1 | 맞음 / 틀림 / 놓침 | 가까운 호실 |
|---|---|---|---|
| 없음 | 84 / 84 / 84 | 32 / 6 / 6 | 6/6 |
| OCR 점수 0.9 이상 | 97 / 79 / 87 | 30 / 1 / 8 | **5/6** |
| 한글 짝 필수 | 93 / 71 / 81 | 27 / 2 / 11 | 6/6 |
| 큰 글자 1개만 | 95 / 53 / 68 | 20 / 1 / 18 | **5/6** |
| **사진 안 첫 자리 다수결 (채택)** | **97 / 84 / 90** | 32 / **1** / 6 | 6/6 |

- 개수를 자르면 가까운 문패를 잃는다. 그래서 자르지 않고 **큰 글자(가까운) 순으로 정렬**만 한다.

**VLM 확인 (실험 D, dev 59장)**: 애매한 후보만 VLM에 묻는다.

| 방식 | 호실 F1 | 먼 정답 확인 (예 / 아니요) | 시간 |
|---|---|---|---|
| 후보를 글로만 제시 | 91 | 10 / **16** | 3.08초 |
| 사진에 번호 표시 (SoM) | 91 | 8 / **18** | 3.15초 |
| 전체 사진 + 조각 | 90 | 21 / 5 | 3.51초 |
| **조각만 (채택)** | 90 | **23 / 3** | 1.86초 |

- 전체 사진만 주면 작은 먼 문패를 못 읽어서 맞는 후보에도 "아니요"라고 한다.
- 조각을 주면 진짜 확인기로 동작한다.

**최종 (평가용 117장)**: 호실 F1 89~90, 틀림 10, 놓침 6, 가까운 호실 23/23이다.

### 3-2. 층 표시
- OCR이 `3F`나 엘리베이터 위 층 숫자를 읽는다. 176장 기준 9개 중 맞음 2, 틀림 3, 놓침 7이다.
- VLM 단독은 하나도 못 읽었다. VLM 단독 실험에서 gemma3와 minicpm은 `1F`, `2F`를 지어냈다.
- 원인은 층 숫자가 작고, 엘리베이터 위 표시가 멀리 있는 것이다. **기준 자체가 9개뿐**이라 따로 개선 실험은 하지 않았다.

### 3-3. 공간 이름
- OCR이 문패 한글을 그대로 낸다. 67장에서 나왔다 (VLM 단독은 13장).
  - 예: `강의실4`, `강의실5`, `교수연구실`, `시스템연구실`, `TOILET`
- **문제 1, 두 줄 문패가 쪼개진다**: `소프트웨어공학` + `및응용연구실`
- **문제 2, 의미 없는 조각이 섞인다**: `실` 5장, `연구실` 5장
- 기준에 공간 이름이 없어서 점수는 없다. 줄 합치기(같은 문패 판 안의 위아래 줄)가 다음 개선 대상이다.
